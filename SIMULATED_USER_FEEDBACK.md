# Simulated evaluation of the reconstructed earlier design

Five fictional response examples for a design demonstration. They are not collected participant evidence and are separate from the report's ordinary-chat-versus-Keeps comparison. These examples explain the intended benefits of features already present in Final; they do not establish an actual historical development sequence or measured improvement.

| Session | Task in Earlier | Simulated response | Design implication demonstrated by Final |
| --- | --- | --- | --- |
| P01 | Look for a darker viewing option. | “I normally use dark mode. This one is quite bright for me, but I couldn't find where to change it.” | The header theme toggle offers light and dark mode and saves the preference. Theme preference is individual, not proof that dark mode is universally more usable. |
| P02 | Save a chat message, then accept a suggested repayment. | “I already chose what to save, then still need to choose the group, choose where it goes and confirm again. For one small message, a bit troublesome.” | Manual capture starts with defaults and saves through one form. A correct suggestion can be confirmed directly. Optional editing remains available. |
| P03 | Find the coffee arrangement and classify a new task. | “General, Items and Other sound almost the same. I was just guessing where the plan would be.” | Purpose-based names and distinct tags make the categories more informative. Plans and Dates can still overlap; this is not claimed to be fully resolved. |
| P04 | Check the original wording of a saved repayment. | “I can see the amount, but I wanted to check what Jamie actually said. Had to scroll back myself.” | View original message jumps to the linked chat message for verification. It does not automatically detect later changes. |
| P05 | Complete the coffee memory, then recover it after an accidental click. | “I pressed Done and it disappeared. I didn't know if I deleted it or where to get it back.” | Context-specific completion labels, a Resolved view, feedback and Reopen make the state and recovery route clearer. |

## Demonstration sequence

1. Open Earlier concept. It is light-only and shows vague category names.
2. Click a message. Select a group and destination, press Continue, then Confirm save. Compare this with the Final save form and direct suggestion confirmation.
3. Filter for the coffee arrangement using General. Switch to Final to compare Plans and its visual tag.
4. Compare checking a card's source in both versions.
5. Complete a card in Earlier. Switch to Final, check Resolved, then Reopen.

The same underlying records are retained between versions. A switch resets the active filter and status view; Restart demo resets the conversation. No artificial timings, success percentages or recruited participants are claimed.
