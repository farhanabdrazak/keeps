DESIGN COMPARISON

Earlier concept and final interface

The earlier concept is reconstructed to demonstrate UX limitations. It is not a recovered historical build or evidence of a prior user test. The final interface is the existing repository design.

  • Theme choice. Earlier: light mode only. Final: a working light/dark toggle that remembers the preference.
  • Saving effort. Earlier: choose a group and destination, Continue, then confirm on a second screen. Suggestions also require the editor. Final: useful defaults, one-step suggestion confirmation and a single save form.
  • Category clarity. Earlier: Numbers, General, Items, Misc, Other and Notes, with uniform tags. Final: Money, Plans, To-Dos, Recommendations, Dates and Decisions with distinct tags.
  • Checking context. Earlier: find the message manually. Final: View original message.
  • Completion and recovery. Earlier: Done hides the item with no resolved view. Final: contextual actions, Resolved and Reopen.

Both views use the same session data. Switching resets the current filter, not your memories. These differences support a simulated evaluation; the five example responses are documented in the repository. Plans versus Dates overlap remains a possible refinement, not a claimed fix.

Five illustrative usability-test responses

Hypothetical feedback for demonstrating the design iteration — not responses collected from recruited participants.

P01 · Theme choice
“I normally use dark mode. This one is quite bright for me, but I couldn't find where to change it.”

Addressed in Final: A light/dark toggle that keeps the user's preference.

P02 · Saving effort
“I already chose what to save, then still need to choose the group, choose where it goes and confirm again. For one small message, a bit troublesome.”

Addressed in Final: Useful defaults and direct suggestion confirmation.

P03 · Category clarity
“General, Items and Other sound almost the same. I was just guessing where the plan would be.”

Addressed in Final: Clear, purpose-based category names and distinct tags.

P04 · Source context
“I can see the amount, but I wanted to check what Jamie actually said. Had to scroll back myself.”

Addressed in Final: View original message links each memory to its source.

P05 · Recovering completed items
“I pressed Done and it disappeared. I didn't know if I deleted it or where to get it back.”

Addressed in Final: Resolved status, completion feedback and Reopen.
